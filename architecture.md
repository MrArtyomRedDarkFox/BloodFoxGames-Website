# Архитектурная документация: Game Store & Game Library API

## 1. Описание системы и пользовательский сценарий
**Game Store & Game Library API** — веб-сервис для каталогизации, покупки и управления цифровой библиотекой видеоигр.

* **Основной пользовательский сценарий:**
  1. Пользователь просматривает каталог игр через клиентское приложение.
  2. При получении списка игр система в первую очередь проверяет наличие данных в оперативном кэше Redis.
  3. При покупке игры пользователь отправляет REST-запрос, который проходит через API Gateway в `API Service`.
  4. Транзакция сохраняется в базе данных PostgreSQL, после чего инвалидируется/обновляется кэш в Redis, а внешние сервисы (Payment Gateway и Email Service) получают соответствующие уведомления для обработки оплаты и отправки чека.

---

## 2. Описание компонентов по уровням C4

### C4 Level 1 — Context (Контекст)
* **User / Client:** Пользователь системы (веб- или мобильный клиент).
* **Game Store System:** Центральная система магазина и библиотеки игр.
* **Payment Gateway:** Внешний сервис обработки платежей.
* **Email Service:** Внешняя служба рассылки электронных писем и чеков.

### C4 Level 2 — Container (Контейнеры)
* **User / Client:** Клиентское приложение.
* **API Gateway / LB (Nginx):** Единая точка входа, выполняющая L7-маршрутизацию и балансировку.
* **API Service (Spring Boot):** Основной бэкенд-контейнер с бизнес-логикой.
* **PostgreSQL:** Основная реляционная база данных для хранения пользователей, заказов и каталога.
* **Redis:** Дополнительный компонент — оперативный кэш для популярного контента.

### C4 Level 3 — Component (Компоненты API Service)
* **StoreController / LibraryController:** Слой REST-контроллеров для приема HTTP-запросов витрины и библиотеки.
* **StoreService / LibraryService:** Слой бизнес-логики покупки и управления купленными играми.
* **GameRepository (Spring Data JPA):** Слой доступа к реляционной БД PostgreSQL.
* **CacheManager (RedisTemplate):** Слой управления кэшированием в Redis.

---

## 3. Обоснование выбора дополнительного компонента (Redis Cache)
В качестве дополнительного компонента выбран **Redis Cache**.
* **Причина:** В онлайн-магазине видеоигр соотношение операций чтения (просмотр каталога, страниц игр, профилей) к операциям записи (покупка) составляет примерно 9:1. Кэширование витрины и часто запрашиваемых данных в Redis позволяет снизить задержку ответа (latency) и защищает БД PostgreSQL от перегрузки при высокой посещаемости.
