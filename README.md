# BloodFoxGames — Game Store & Game Library

Учебный проект DevSecOps: магазин видеоигр и личная библиотека пользователя на основе микросервисов, PostgreSQL и Docker Compose.

## Возможности

- каталог игр с описаниями и ценами;
- регистрация и вход пользователя;
- покупка игры и отображение её в личной библиотеке;
- автоматическое HTTP-уведомление при покупке;
- BCrypt-хеширование паролей новых аккаунтов;
- адаптивный веб-интерфейс в тёмном игровом стиле.

## Архитектура и сервисы

| Компонент | Технологии | Порт | Назначение |
|---|---|---:|---|
| Frontend | HTML, CSS, JavaScript, Nginx | 3000 | Витрина, регистрация, магазин и библиотека; Nginx проксирует `/api/*` в Game Store API |
| Game Store Service | Java 17, Spring Boot, Spring Data JPA | 8080 | Каталог, регистрация/вход, покупка и библиотека |
| Users Service | Java 17, Spring Boot, Spring Data JPA | 8081 | Отдельный сервис базовых пользовательских записей |
| Notifications Service | Python, FastAPI, Uvicorn | 8082 | Приём и логирование уведомлений о покупках |
| PostgreSQL | PostgreSQL 16 | 5432 | Постоянное хранение данных через Docker volume `db_data` |

Архитектурные материалы C4: [architecture.md](./architecture.md), [architecture-c4.png](./architecture-c4.png).

## Запуск в Ubuntu / Linux

Для существующего тома PostgreSQL POSTGRES_PASSWORD должен совпадать с паролем роли, установленным при инициализации базы. Изменение .env само по себе не меняет пароль существующей БД. Файл .env исключён из Git.

```bash
cp .env.example .env
sudo docker compose config
sudo docker compose up --build -d
sudo docker compose ps
```

Открой веб-сайт: **http://localhost:3000**.

Остановка контейнеров без удаления данных:

```bash
sudo docker compose down
```

Не используй `docker compose down -v`, если нужно сохранить текущую базу данных: флаг `-v` удаляет том.

## Пользовательский сценарий

1. Открой `http://localhost:3000`.
2. Нажми **Создать аккаунт**, введи имя, email и тестовый пароль от 6 символов.
3. Войди под теми же данными.
4. Перейди в **Магазин** и нажми **Купить игру**.
5. Открой **Библиотека**: купленная игра должна там отображаться.
6. Проверь автоматическое уведомление: `sudo docker compose logs --tail=50 notifications-service`.

## REST API для проверки

| Метод | Endpoint | Назначение |
|---|---|---|
| `GET` | `/api/v1/games` | Получить каталог игр |
| `GET` | `/api/v1/games/{gameId}` | Получить карточку игры |
| `POST` | `/api/v1/users/register` | Создать аккаунт в магазине |
| `POST` | `/api/v1/users/login` | Проверить логин и BCrypt-пароль |
| `GET` | `/api/v1/users/{userId}` | Получить профиль |
| `POST` | `/api/v1/users/{userId}/buy/{gameId}` | Добавить игру в библиотеку и отправить уведомление |
| `GET` | `/api/v1/users/{userId}/library` | Получить библиотеку |
| `GET` | `http://localhost:8082/health` | Проверить сервис уведомлений |

Пример проверки каталога:

```bash
curl -i http://localhost:8080/api/v1/games
```

Пример проверки уведомлений:

```bash
curl -i http://localhost:8082/health
```

## Пароли и ограничения прототипа

Новые аккаунты в Game Store хранят пароль как BCrypt-хеш; поле пароля скрыто в JSON-ответах. Аккаунты, созданные до добавления BCrypt, могут содержать пароль в старом формате и не смогут пройти новую проверку входа — используй свежую тестовую регистрацию.

Это учебный прототип, не готовая production-платформа: сейчас браузер сохраняет в `localStorage` только отображаемые данные пользователя (ID, имя и email), но API пока использует ID пользователя в URL и не проверяет серверную сессию/JWT и владение аккаунтом. Для реального развёртывания необходимо добавить полноценную серверную аутентификацию и авторизацию, валидацию, ограничение запросов и управление секретами.
